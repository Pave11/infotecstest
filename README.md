TCP File Transfer (C++ / Linux)

Консольное клиент-серверное приложение для передачи файлов по TCP/IP (IPv4).
Реализация выполнена в рамках тестового задания на позицию C++ разработчика.

Проект состоит из двух приложений:
    server_app — TCP сервер, передающий файл клиентам
    client_app — TCP клиент, получающий файл от сервера

Сервер поддерживает одновременное обслуживание нескольких клиентов с использованием потоков (std::thread).
Передача осуществляется фиксированными порциями (chunk), размер которых задаётся клиентом.

ОС: Linux
Компилятор: g++ (C++17)
Протокол: TCP (IPv4)

Сборка

    В корне проекта:

        make

    созданы бинарные файлы:

        bin/server_app
        bin/client_app


    Очистка:

        make clean

    Запуск сервера
    По умолчанию (порт 4040):
        ./bin/server_app

    С указанием порта:
        ./bin/server_app -p 4040

    Запуск клиента (получение файла)

    Формат:

        client_app -src <IP>:<путь_к_файлу> -dst <локальный_путь> [-p порт] [-chunk размер]

    Пример:
        ./bin/client_app -src 127.0.0.1:/tmp/file_src -dst /tmp/file_dst


    С указанием размера порции 128 байт:

        ./bin/client_app -chunk 128 -src 127.0.0.1:/tmp/file_src -dst ./file_dst

Аргументы командной строки
Сервер
Опция	Описание
-p	TCP порт (по умолчанию 4040)

Клиент
Опция	Описание
-src	Удалённый источник в формате IP:путь
-dst	Локальный путь для сохранения файла
-p	TCP порт (по умолчанию 4040)
-chunk	Размер порции передачи (по умолчанию 1024 байт)


Прогресс передачи
Во время приёма файла клиент выводит прогресс:
<передано XX байт>

Файл сохраняется во временный .tmp файл и переименовывается только после успешного завершения передачи.
При обрыве соединения временный файл удаляется.

Многопоточность
Каждый клиент обслуживается в отдельном потоке (std::thread)
Основной поток сервера принимает входящие соединения
Используется std::atomic<bool> для корректной остановки сервера

Обработка сигналов
Сервер обрабатывает:
SIGINT (Ctrl+C)
SIGTERM

При получении сигнала:
    прекращается приём новых соединений
    закрывается основной сокет
    сервер завершает работу корректно

Тестирование

Для упрощённого тестирования используется скрипт:
    ./run_test.sh <file_path> <port> <chunk_size> <num_clients>


Пример:
    ./run_test.sh /tmp/file_src 1234 500 6


Скрипт:

    Создаёт тестовый файл (если отсутствует)
    Запускает сервер
    Запускает заданное количество клиентов
    Ожидает завершения клиентов
    Останавливает сервер
    Ограничения текущей реализации
    Передача реализована только от сервера к клиенту
    Нет подтверждения целостности (checksum)
    Нет передачи размера файла заранее
    Нет таймаутов сокета
    Не используется epoll/select (чистая потоковая модель)

Возможные улучшения:
    Передача файла от клиента к серверу
    Передача размера файла перед началом передачи
    Отображение процесса в процентах
    Контрольная сумма (MD5/SHA256)
    Использование SO_REUSEADDR
    Использование пула потоков
    Логирование в файл
    Выделение логики прогресса в динамическую библиотеку
